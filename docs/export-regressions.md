# Public fixture export regressions

`tests/test_export_goldens.py` checks the serialized JSON and GeoJSON output for
the public Stalagmight fixture and each Ariane example listed in
`tests/export_goldens.py`. Every preset registered in
`openspeleo_lib.loop_closure.presets` has its own golden GeoJSON, named with the
full stable preset name:

- `stalagmight-LeastSquaresHorizontalSolver.geojson`
- `stalagmight-LeastSquaresSpatialSolver.geojson`
- `stalagmight-InverseLengthWeightedLeastSquaresHorizontalSolver.geojson`
- `stalagmight-LengthAzimuthWeightedLeastSquaresHorizontalSolver.geojson`
- `stalagmight-InverseLengthWeightedConjugateGradientHorizontalSolver.geojson`
- `stalagmight-TraverseQualityWeightedLeastSquaresSpatialSolver.geojson`
- `stalagmight-InverseLengthWeightedL1SpatialSolver.geojson`

The same naming scheme applies to every public input in the fixture matrix.
Goldens use minified JSON without compression. The measured conversion remains
`stalagmight.geojson`, and unmodified reader output is `stalagmight.json`. New
registered presets automatically participate in generation and comparison;
normal tests require their named expected files to exist.

Reader JSON is compared byte for byte. GeoJSON structure, feature order,
identities, geometry types, and properties remain exact. Only geometry
coordinate numbers permit an absolute difference of one unit at output
precision, using `OSPL_GEOJSON_DIGIT_PRECISION` in
`openspeleo_lib/constants.py`, plus subtraction roundoff. The reference-CG and
traverse-quality-CG methods permit five units at that precision to accommodate
accumulated iterative convergence differences across architectures. Relative
tolerance is disabled so the allowance does not grow with longitude. Platform
math and native solver arithmetic can land on opposite sides of a coordinate
rounding boundary. This comparison policy preserves the stored goldens and
production export precision. Failures report the first differing JSON path
without rendering the full source survey in a pytest traceback.

The `.tml` and `.tmlu` examples with the same stem have separate outputs:
`test_simple.*` and `test_simple-tmlu.*`. TMLU reads plain XML, including its
abbreviated survey record fields, through the same Ariane validation and common
OpenSpeleo model boundary as compressed TML. TMLU writing remains unsupported.

## Source fixtures and geographic test controls

`stalagmight-invalid.stalx` preserves the original invalid survey for rejection
and output-preservation tests. `stalagmight.stalx` is the valid export fixture.
Only the invalid shot's length differs logically: the valid copy uses the
absolute endpoint depth difference plus one metre, following the existing
regression repair. This is a deliberately repaired test fixture, not an inferred
correction to a real survey.

JSON goldens contain the reader's unchanged output. The Ariane examples lack
geographic anchors. For geographic exports only, the harness copies the common
model and gives each START without geolocation the synthetic latitude and
longitude `(40, -70)`. Original coordinates and measurements remain unchanged.
The Gaussian spatial tests independently declare synthetic ENU Z controls of
zero at geographic anchors. The Compass traverse-quality and L1 presets
explicitly fix recorded control depths, matching their source's full-XYZ
anchors; their fixture exports retain that policy rather than replacing those
depths with zero. These controls are test placements, not claims about actual
survey locations.

The walls example introduces a station ID through a CLOSURE identity. The solver
materializes this alias on its disposable view, preserving ID equals FromID and
adding no measured observation. Default measured export retains its existing
orphan filtering, so its feature count can differ from adjusted export.

## Regeneration and verification

Normal tests only read checked-in goldens and write actual results into
temporary directories. Regenerate explicitly from the package root:

```sh
uv run python -m tests.export_goldens /tmp/openspeleo-export-goldens
```

Inspect the generated changes before replacing goldens in `tests/artifacts`. Run
the focused comparisons with:

```sh
uv run pytest tests/test_export_goldens.py
```

These are integration snapshots generated by the current exporters. Independent
numerical ground truth is maintained separately by
`tests/loop_closure_reference.py` and checked by
`tests/test_loop_closure_ground_truth.py`.

Tests and fixtures stay in the repository and are excluded from the source
distribution.
